# libasm

x86-64 アセンブリ(NASM, Intel 構文)で、libc の一部の関数を自作するプロジェクト。

## 関数一覧

| 関数 | ファイル |
|---|---|
| `ft_strlen` | `ft_strlen.s` |
| `ft_strcpy` | `ft_strcpy.s` |
| `ft_strcmp` | `ft_strcmp.s` |
| `ft_write` | `ft_write.s` |
| `ft_read` | `ft_read.s` |
| `ft_strdup` | `ft_strdup.s` |
| `ft_calloc` | `ft_calloc.s` |

## ビルド

```sh
make          # libasm.a を生成
make tester   # 全関数のテストをビルドして実行
make clean    # オブジェクトファイルを削除
make fclean   # libasm.a, テストのバイナリも削除
make re       # 作り直し
```

## アセンブリの解説

### セクションとシンボル

```nasm
section .text      ; 実行コードを置く領域
global ft_strlen   ; 他のファイル(C など)から見えるようにする
```

`global` を付けた名前が、C 側から呼べる関数名になる。

### レジスタ

CPU 内の高速な変数置き場。主なもの:

| レジスタ | 用途 |
|---|---|
| `rax` | 戻り値。計算用にも使う |
| `rdi` | 第1引数 |
| `rsi` | 第2引数 |
| `rdx` | 第3引数 |
| `rcx` | 汎用(カウンタによく使う) |

### レジスタのサイズ別の名前

1つのレジスタは、下位の一部だけを別名で扱える。

| 64bit | 32bit | 16bit | 8bit |
|---|---|---|---|
| `rax` | `eax` | `ax` | `al` |
| `rbx` | `ebx` | `bx` | `bl` |
| `rcx` | `ecx` | `cx` | `cl` |
| `rdx` | `edx` | `dx` | `dl` |
| `rsi` | `esi` | `si` | `sil` |
| `rdi` | `edi` | `di` | `dil` |

- `eax` は `rax` の下位32bit、`al` は下位8bit。
- 1バイト(`char`)を扱うときは8bitの名前、`int` は32bit、ポインタや `size_t` は64bitを使う。
- 32bitレジスタに書き込むと、64bitレジスタの上位32bitは自動で0になる。
- 8bit・16bitに書き込んでも、残りのビットは変わらない。上位に前の値が残るので、1バイトを読むときは `movzx` を使う。

### 呼び出し規約(System V ABI)

C と関数をやり取りするための決まり。

- 引数は `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9` の順に渡される。
- 戻り値は `rax` に入れて `ret` する。
  - 呼ぶ側の C は、関数から戻った直後に `rax` を読む。
  - `int` は32bitなので、`eax` に入っていれば戻り値になる。
  - ポインタや `size_t` は `rax` 全体を使う。
- `rax`, `rcx`, `rdx`, `rsi`, `rdi`, `r8`〜`r11` は自由に壊してよい。
- `rbx`, `rbp`, `r12`〜`r15` は、関数が戻るときに元の値へ戻す。使うなら退避が必要。

### 使う命令

| 命令 | 意味 |
|---|---|
| `mov a, b` | `b` を `a` にコピー。メモリ同士は不可 |
| `movzx a, b` | 小さい `b` を、上位を0で埋めて大きい `a` にコピー(例: `movzx eax, byte [rdi]`) |
| `xor a, a` | `a` を 0 にする(定番の書き方) |
| `inc a` | `a` を +1 |
| `sub a, b` | `a = a - b` |
| `cmp a, b` | `a` と `b` を比べ、結果をフラグに残す。値は変えない |
| `jmp label` | 無条件でジャンプ |
| `je label` | 直前の `cmp` で等しければジャンプ |
| `jne label` | 直前の `cmp` で等しくなければジャンプ |
| `jl label` | 直前の `cmp` で左が小さければジャンプ(符号付き) |
| `neg a` | `a` の符号を反転(`a = 0 - a`) |
| `push a` | `a` の値をスタックに積む(`rsp` を8下げて書く) |
| `pop a` | スタックの一番上を取り出して `a` に入れる(`rsp` を8上げる) |
| `call f` | 関数 `f` を呼ぶ。戻り先を覚えて `f` へ飛ぶ |
| `syscall` | カーネルに処理を頼む。番号は `rax`、引数は `rdi`, `rsi`, `rdx` |
| `ret` | 呼び出し元へ戻る |

`cmp` は結果をフラグに残すだけで、その直後の `je` / `jne` / `jl` などがフラグを見て分岐する。

### メモリアクセス

`[ ]` で囲むと、そのアドレスの中身を読み書きする。

```nasm
byte [rdi + rax]   ; rdi の指す先から rax バイト目の 1 バイト
```

サイズ指定(`byte`, `word`, `dword`, `qword`)が必要。メモリからメモリへ直接 `mov` はできないので、いったんレジスタを経由する。

### ラベル

`.loop` のように `.` で始まるラベルは、直前の関数ラベルに属するローカルラベル。ループや分岐の飛び先に使う。

### スタック

メモリの一部で、「積んで、上から取る」置き場所。`rsp` が一番上を指す。

- `push` で積み、`pop` で取り出す。最後に積んだものが最初に出る。
- `call` の前後で値を残したいときに、一時的な退避先として使う(`call` が `rax` などを壊すため)。
- `push` と `pop` は同じ数だけ書く。ずれると `ret` の戻り先が狂って落ちる。
- `call` する時点で `rsp` は16の倍数でなければならない。関数に入った直後は8ずれているので、`push` を1回挟むと揃う。

### システムコール

`syscall` 命令は、カーネル(OS 本体)に処理を頼む。画面やファイルへの入出力のように、プログラムが直接できないことはカーネルがやる。

| レジスタ | 役割 |
|---|---|
| `rax` | 頼む処理の番号 |
| `rdi`, `rsi`, `rdx` | 第1〜第3引数 |

- 番号は Linux x86-64 で `read` = 0、`write` = 1。
- 結果は `rax` に返る。成功なら値(書いた / 読んだバイト数)、失敗なら `-errno`(`-4095`〜`-1`)。
- 関数の引数と syscall の引数がほぼ同じレジスタなので、`ft_write` / `ft_read` は引数を動かさずに使える。

`ft_write` の中で実際に書き込みをしているのは `syscall` の1行。`ft_write` は次の3つをするだけの取り次ぎ。

1. `rax` に syscall 番号を入れる。
2. `syscall` でカーネルに頼む。
3. 結果が負なら `errno` を設定して `-1` を返す。

`ft_read` も番号が `0` に変わるだけで、構造は同じ。

### errno

関数が失敗した理由を入れておく番号(グローバル変数)。戻り値の `-1` だけでは理由が分からないため、別に番号を残す。

- `EBADF`(9): 無効なファイルディスクリプタ
- `ENOMEM`(12): メモリ不足

`errno` はスレッドごとに別の場所にあるので、置き場所のアドレスを `__errno_location()` に聞いて、そこへ値を書く。`.error` の流れ:

1. `neg rax` で `-errno` を正の `errno` に直す。
2. `push rax` で退避する(`call` で `rax` が上書きされるため。`rsp` の16バイト揃えも兼ねる)。
3. `call __errno_location wrt ..plt` で `errno` のアドレスを `rax` に得る。
4. `pop rdx` で退避した値を取り出す。
5. `mov [rax], edx` で `errno` に書く(`errno` は `int` なので32bit)。
6. `mov rax, -1` で戻り値を `-1` にして `ret`。

### 外部関数の呼び出し

アセンブリから C の関数(`malloc`、`__errno_location` など)を呼べる。同じ呼び出し規約(System V ABI)を守っているため。

```nasm
extern __errno_location           ; 外部の関数だと宣言する
call __errno_location wrt ..plt   ; 戻り値は rax
```

- `extern` で、自分のファイルにない関数だと宣言する。
- `wrt ..plt` は、共有ライブラリの関数を PLT(中継テーブル)経由で呼ぶ書き方。libc は実行時に載る場所が変わり、`-no-pie` も使えない(PIE)ため、直接 `call` するとリンクできない。
- 引数は `rdi`, `rsi`, ... に入れてから `call` する。呼んだ後も使う値は退避しておく。

### C とアセンブリの関係

C のソースは、コンパイラ(`gcc`)がアセンブリ、機械語へと変換する。

```
C のソース → (コンパイラ) → アセンブリ → (アセンブラ) → 機械語 → (リンカ) → 実行ファイル
```

- libc の関数(`malloc` など)はほとんど C で書かれている。`syscall` まわりなど一部だけがアセンブリ。
- C から `ft_strlen` を呼べるのも、アセンブリから `malloc` を呼べるのも、同じ呼び出し規約を守っているから。
- `gcc -S foo.c` で、C から生成されたアセンブリを見られる。
